# Shawared

Arabic poetry as it is recited: audio with the verses lighting up, translations, explanations and word meanings. One Expo codebase for iOS, Android and web. Content is JSON in git; there is no database yet.

## Where code lives

- `content/` – the poems, poets and reciters, written by hand. Format: [docs/content-format.md](docs/content-format.md); how to write them: [docs/writing.md](docs/writing.md). `content/queue.md` lists recordings waiting to be made into poems.
- `apps/app` – the Expo Router app. `src/app` holds routes only: Arabic at `/…`, the same routes for English under `src/app/en`. The five tabs (`(tabs)/`) are home, poets, reciters, themes and the reader's library; every page opened from them (a poem, a poet, a reciter, a theme, the meter index, a meter, a playlist) sits on the root stack above the tabs, so back retraces the reader's steps. Screens live in `src/features/<feature>`, shared pieces in `src/components/ui`, plumbing in `src/lib`. `src/server` runs only while web pages are rendered ahead of time: each page's data (`loader`), its title and description (`generateMetadata`) and its params.
- `apps/app` for iOS and Android: `app.json` and `app.config.ts`, whose version is `package.json`'s and whose build numbers follow from it (1.2.3 builds as 1002003). `ios/` and `android/` are generated (`expo prebuild`), never committed. The icons and splash images in `assets/app`, and the artwork lock screens show with a recitation (`public/artwork.png`), are drawn from the mark by `scripts/app-icons.ts`. Release builds read content from shawared.com and recordings from audio.shawared.com; dev builds from the dev server. `plugins/with-release-signing.js` signs Android release builds with the apps' shared upload key when `ANDROID_UPLOAD_KEYSTORE_FILE` names it.
- `packages/contracts` – zod schemas: the strict authoring format (`source.ts`), the lenient published format the app downloads (`published.ts`) and addresses.
- `packages/listening` – pure playback logic: timelines, the line being recited, previous/next/repeat, word-note lookup. No React, tested with vitest.
- `packages/design` – colours, fonts, the mark, the gap scale, the follow-pause rule, and ink-trimmed text boxes (`type.ts`, see [docs/typography.md](docs/typography.md)).
- `scripts/` – making poems, in the order [docs/writing.md](docs/writing.md) uses them: `intake.ts` (a recording's audio, silences, loudness and transcript), `shamela.py`, `shamela-old.py` and `archive.py` (finding and fetching editions: shamela search and pages, the old shamela's diwans, scanned editions on archive.org), `collate.py` (comparing editions bayt by bayt), `tashkeel.ts` (harakat in the house style), `audio.ts` (the app audio at −20 LUFS), `align.py` (timings), `variants.py` (which reading the reciter says), `verify.py` (every half transcribed again and compared), `notes.ts` (fills and lists the words each note points at), `preview.ts` (a review page per poem). Then `check.ts` (content checker), `build-content.ts` (publishes content into `apps/app/public`), `kashida.ts` (sets every half of a poem to one width, run by the publish step) and `sitemap.ts` (sitemap.xml for the exported site).
- `design/` – the HTML prototypes the app follows (0.3 identity, 0.4 listening).
- `media/` – downloads, app audio and work files. Gitignored. Recordings are published to `audio.shawared.com` with `bun run audio:upload` ([docs/web-deployment.md](docs/web-deployment.md#audio)); `media/test-audio` holds the browser tests' silent stand-ins.

## Commands

Run through mise so bun, node and caddy match `mise.toml`: `mise exec -- bun run <script>`.

- `bun run dev` – publishes content, then starts Expo for web on port 8081.
- `bun run check` – content check, typecheck, unit tests.
- `bun run test:e2e` – Playwright against the dev server; `BASE_URL=http://localhost:8090` tests the production build instead. Includes the overlap audit (`tests/typography.spec.ts`).
- `bun run web:build`, then `bun run web:serve` – every page rendered ahead of time, in both languages, plus the sitemap, served through Caddy on port 8090.
- `bun run web:build:test`, then `bun run test:release` – the browser tests and the hosting tests against the export as Cloudflare serves it, with silent stand-ins for the recordings. CI runs these ([docs/web-deployment.md](docs/web-deployment.md)).
- `bun run deploy:check` – the release build (audio from `audio.shawared.com`) and Wrangler's dry run of its deploy.
- Each commit pushed to main deploys to shawared.com once its checks pass, and only moves the site forward along main ([docs/web-deployment.md](docs/web-deployment.md#deploys)).
- `bun run store:check`, `bun run store:screenshots` – the stores' listing (`apps/app/store`): its check, and its images redrawn from the test build. `bun run fastlane:check` loads the release lanes.
- The apps are released by release-please from Conventional Commits, to the App Store, Google Play and AppGallery ([docs/releasing.md](docs/releasing.md)).

## Rules

- Commit titles are Conventional Commits, pushed to main or not: `fix:` and `feat:` release the apps when they change `apps/app` or `packages/`; `content:`, `docs:`, `test:`, `ci:`, `build:`, `chore:` and `refactor:` release nothing. A title that isn't one releases nothing, so a change to the apps under it never reaches the stores ([docs/releasing.md](docs/releasing.md#commit-messages)).
- Every bayt the app shows is set to its poem's measure with kashida (`Half`/`Measure` in `components/ui/Measure.tsx`) ([docs/typography.md](docs/typography.md#verses-at-one-width)). Kashida is shown, never written into content; find verse words in tests with a pattern that allows tatweel.
- The verse text follows the recording, unless the reciter is clearly wrong (his word breaks the meter, the grammar or the sense, or is no word at all): then it follows the editions, and the word's note says what he says. Where editions differ, `scripts/variants.py` decides what the reciter says; word cards show the dictionary form in `head`. Harakat follow the house style in `packages/contracts/src/tashkeel.ts`.
- Transcription (`intake.ts`, `verify.py`) runs tafrigh; set `TAFRIGH` to a CUDA build of it when there's an NVIDIA GPU, which is many times faster than the CPU build.
- Arabic verses are always on screen and always right-to-left. The UI flips with the language: English is left-to-right, including the progress bar and controls.
- Saffron (`accent`) is for the nuqta and active marks, never body text.
- Every `Text` takes a role from `useType()` (`apps/app/src/lib/type.ts`). Never set font size, line height or vertical margins/padding on a `Text`; space texts with container gaps from `space`. Bordered labels wrap their `Text` in a `View` (`Chip`, `Tag`). See [docs/typography.md](docs/typography.md).
- Text alignment uses `start` from `useSettings()` or `ARABIC` from `lib/align`; native platforms read left/right as start/end inside right-to-left layouts. A `TextInput` doesn't: it takes `inputAlign` (physical sides on every platform).
- Pages use `ListPage` or `PageFrame` (`features/library/Page.tsx`): on phones the fixed `TopBar` with back and the page's title, over the girih band; on wide windows the sidebar at the start (`features/navigation/Sidebar.tsx`: the cover tile, the sections, what the reader keeps, the counts), and beside it the page's column with the girih band, back and the settings at its top and the player bar (`features/player/PlayerBar.tsx`) along its bottom. The poem page is one layout (`features/listening/layouts.tsx`): stacked on phones, with the explanation in a sheet; on wide windows the explanation is the sidebar, under the tile and the sections in a row. Titles use `barTitle`/`pageTitle` (Readex: Reem Kufi has no ṭ, ḥ or ʿ); Reem Kufi is for the wordmark.
- Directional icons (play, previous, next, back) are drawn left-to-right and mirrored by `Icon` in Arabic. Don't flip them by hand.
- Hover-only highlights: on the web a tapped control keeps focus, so don't style `focused`.
- Use `Dir` for a box with its own direction. React Native Web ignores the `direction` style.
- Under `Link asChild`, pass a flattened style object, never an array or a function.
- A link that is text uses `TextLink` (`components/ui/TextLink.tsx`): it spans its text, never the page. Rows and cards are links tapped anywhere. `tests/links.spec.ts` checks every text link.
- Fast-changing values (the playback clock) go through `lib/store` with a selector, so only what reads them re-renders.
- Published files are read leniently. A change older apps can't read goes in a new `v2/` folder.
- Build in-app paths with `paths` (`lib/routes`) and `href()` from `useSettings()`, so English stays under `/en` on the web. On the web the address decides the language; the apps keep it in settings.
- Phones and wide windows (from `WIDE_MIN`, 960) are laid out differently, and on the web CSS chooses, so one page rendered ahead of time is right at every width and the browser shows it before the app runs (`lib/responsive.tsx`). Never render by the window's width on the web: make a style that differs with `responsive(phone, wide)` at a module's top level and use it through `useLayout().style`; a size computed while rendering with `useLayout().value` and `scale`; what shows in one layout only with `<Only on="phone" | "wide">` (small pieces: bars, a few controls, never a poem's verses). A page rendered ahead of time holds both layouts' pieces; a page moved to afterwards, drawn in the browser, holds only its window's, and the other's when the window crosses WIDE_MIN. For what a tap does, `isWide()`. The apps have no CSS: there `useLayout` follows the window's width and `Only` renders only what shows. `tests/first-paint.spec.ts` holds the scripts back and checks the layout, that nothing moves when the app takes over, and resizing.
- Web pages are rendered ahead of time in the day theme. Anything else the server can't know (saved settings, the address's query) waits until the page is live: use `useHydrated` and `useWindowWidth` (`lib/viewport`), never `useWindowDimensions`. The night theme holds the first paint until then (`app/+html.tsx`).
- Route files come in Arabic and English twins and stay identical apart from `LANG`. They reach `src/server` only through `await import()` inside `loader`, `generateMetadata` and `generateStaticParams`.
- Moving to another page must never wait on the network or suspend: Expo shows an empty screen while a page suspends. So a page reads its loader data only through `useInitial` (`lib/initial`), which gives it to the page the browser opened and nothing to pages moved to; those load their files through `lib/content`. Never call `useLoaderData` directly. Routes are in the main bundle (`asyncRoutes: false` on the expo-router plugin, whose default splits them). Links to a poem or a person fetch its file on hover or press (`usePrefetch`), and a poem draws its first rows before the rest. `tests/library.spec.ts` ("never shows an empty screen") guards this.
- The privacy policy and contact & support (`/privacy`, `/support`) are the pages the stores link, beside About Shawared and the terms of use (`/about`, `/terms`); each of the four ends with links to the other three. Their texts are in `features/about/texts.ts`, where a paragraph links with `[its words](address)`. Say anything new the apps or the site store, send or load in the privacy policy, and change `PRIVACY_UPDATED` or `TERMS_UPDATED` with its page.
- Phones' browsers are offered the app (`app/+html.tsx`, `appBanner` in `lib/stores.ts`). Safari on iPhones and iPads gets Apple's banner (`apple-itunes-app`), which opens the app at the page. Other phones' browsers get the app bar above the page, drawn before the app's scripts run, with `#root` moved down to make room: Android browsers open the app at the same page through its `shawared://` address (Google Play without it), apps' browsers on Android and other iOS browsers get the store page, Huawei phones AppGallery's. Computers, HarmonyOS NEXT and installed web apps get no bar, and `/app` neither. Open pauses the player (`OPEN_APP_EVENT`); × hides the bar for the visit. `tests/app-banner.spec.ts` checks each kind of phone.
- shawared.com/app (and `/en/app`) is the address to share for the apps. `app/+html.tsx` gives it a script in its head (`lib/stores.ts`) that sends a phone on to its store before the app's scripts run: iPhones and iPads to the App Store, Huawei's browser and apps' web views on Huawei phones to AppGallery, other Android phones to Google Play. Anything else, HarmonyOS NEXT included, gets the page (`features/stores`): the stores' own badges, and on wide windows a QR code of the page, drawn by `scripts/store-qr.ts`. The apps' route goes home. The page stays out of the sitemap and search engines, and `tests/app.spec.ts` checks each kind of device.
- shawared.com's links open the apps at the same page ([docs/web-deployment.md](docs/web-deployment.md#app-links)): Apple's and Android's files in `apps/app/public/.well-known`, and the associated domain and verified filter in `app.json`, claim the pages the apps have and their `/en` twins. About, privacy, terms, support and playlists stay on the web. A new route fails `scripts/app-links.test.ts` until it's claimed in both files or listed as web-only.
- Long lists use `ListPage` (virtualized). There is one player for the whole app (`features/player`); screens talk to it through `usePoemPlayback`. It plays a queue (the list a poem was opened from), through expo-audio's playlist on the apps and one `<audio>` element with the Media Session on the web, so poems play on with the screen locked and the lock screen's buttons work ([docs/playback.md](docs/playback.md)).
- What the reader keeps (favourite poems, poets and reciters, and playlists) is saved on the device only, through `lib/saved.ts`; its rules are in `features/saved/model.ts`, tested without storage. Web pages render it only once live. A playlist's page takes its id in the query (`/playlist?id=`), and the library and playlists stay out of the sitemap and search engines. Recordings downloaded to listen to offline are the apps' (`lib/downloads.ts`; `downloads.web.ts` does nothing), and the player plays a downloaded recording from its file ([docs/playback.md](docs/playback.md#downloads)).
- Report web checks and native device checks separately. Native audio has been checked on an Android emulator only (playback, background, the media notification's service), before the player moved to a playlist; the lock screen, continuous play and iOS audio still need a device: [docs/playback.md](docs/playback.md#device-checklist) lists what to try.
